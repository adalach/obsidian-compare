# Developing Compare

## Build and test

```bash
npm install
npm run build   # typecheck, then a minified main.js
npm run dev     # watch build with an inline source map, for debugging
npm test        # the diff, line pairing, word, copy, gap and heading tests in test/
npm run lint    # eslint with Obsidian's plugin review rules (eslint-plugin-obsidianmd)
```

Obsidian loads `main.js`, `manifest.json` and `styles.css` from `<vault>/.obsidian/plugins/compare/`. Each build copies the three files there: into the folder named by the `COMPARE_PLUGIN_DIR` environment variable, or else into `~/Documents/Obsidian Vault/.obsidian/plugins/compare/` when that folder exists. After a rebuild, turn the plugin off and on under **Settings → Community plugins** to load the new code.

## How it works

`src/main.ts` wires the parts together and keeps the state: the pair being compared, live updates, the differences shown in the panel and the scroll sync. Class names and CSS classes (`markdowncompare-…`) keep the plugin's first name, MarkdownCompare; the plugin id is `compare`, and the panel's view type is `compare-diff-view`, so Compare loads next to an old MarkdownCompare install.

`src/compare/comparison.ts` starts, refreshes and ends a comparison. A comparison is a pair of tabs (`ComparePair`), not "the two notes on screen": it is set when a comparison starts and ends when either tab closes or shows another note, so other panes, sidebars and pop-out windows do not affect it. `compareNotes` compares the two visible notes when there are exactly two, and otherwise opens the note picker (`src/ui/NotePickerModal.ts`) for the current note. `src/compare/panes.ts` finds tabs: the visible notes outside the sidebars, the current note, and a tab for the picked note (an already visible tab, a background tab in another tab group brought to the front, or a new split to the right). Left and right are ordered by position on screen, so focus does not swap them. `src/commands/registerMenus.ts` adds the file, tab and two-file menu items. The picker and menus offer every file Obsidian opens in its editor (`opensInEditor`): Markdown, plus extensions another plugin registered for the editor, such as `.tex`. Obsidian has no public API for that lookup, so it reads `app.viewRegistry` and falls back to Markdown only.

`src/headings/headings.ts` finds each file's headings by its extension: `#` headings in `.md` (outside code fences), sectioning commands in `.tex` (`src/headings/latex.ts`, outside comments and verbatim environments), none in other files. `src/diff/highlights.ts` turns two texts into line and character highlights and the list of differences. Headings found in both files (`src/scroll/headingAnchors.ts`, matched by title, so a Markdown heading can match a LaTeX section) are fenced with sentinel lines before the line diff (`src/diff/myersDiff.ts`), so lines are only matched within the same section. Between anchors (the sentinels, and equal lines that contain letters or digits) `src/diff/align.ts` pairs the lines again: an order-preserving alignment that maximises similarity, pairing identical lines first and then lines with at least half of their words in common (Dice coefficient). Equal blank lines are not anchors, because they can match across an edit and split a paragraph from its edited version (for example after a table was inserted above it). Stretches over 250,000 line pairs keep the line diff and pair removed and added lines by position. Each run of paired lines, or of lines without a partner, is one difference; paired lines, and a single line replaced by a single line (`DiffHunk.paired`), get word marks, while other replaced lines show as removed and added. `src/diff/words.ts` finds the changes inside a pair of lines by whole words (a line diff over word, space and punctuation tokens), joining changes separated only by spaces; each change can be copied on its own (`copyChangeEdit` in `src/diff/copy.ts`, `copyChangeAt` in `src/compare/copyDifference.ts`, tested in `test/words.test.ts`). `src/editor/diffHighlight.ts` draws the highlights as CodeMirror decorations; Live Preview draws tables, callouts, embeds and other blocks as widgets in place of their lines, where line decorations do not show, so `src/editor/blockHighlight.ts` gives each such widget (a `BlockType.WidgetRange` block) a `markdowncompare-block-…` class from the highlights on its lines, after every editor update and DOM change. In a rendered table each row stands for one source line (the delimiter line has none), so the word marks of a row are mapped to their cells (`src/editor/tableCells.ts`) and shown with the CSS Custom Highlight API (`::highlight(markdowncompare-removed-words)` and `-added-words`), which colours text ranges without changing the table's DOM, so cell editing keeps working; a cell whose rendered text differs from its source (formatting, links) is matched by the marked text, or highlighted as a whole. A capture-phase `mousedown` listener in `src/compare/copyDifference.ts` makes Cmd+click on such a block copy its first difference, before the block's own click handling (such as editing a table cell). `src/scroll/scrollSync.ts` keeps the two editors scrolled to the same section, and `src/ui/DiffView.ts` is the right-sidebar panel.

With **Line up matching text** on (`src/ui/SettingsTab.ts`, saved in `data.json`), `src/compare/alignment.ts` keeps the matched lines (equal lines and edited pairs, `matched` from `computeHighlights`) level. Each editor keeps its matched line starts in a state field mapped through edits, and blank block widgets (`src/editor/gaps.ts`, a state field because block widgets change the editor's height). `GapAligner` reads the line tops from CodeMirror's height map, subtracts its own gaps, and gives each matched line whose top differs a gap on the higher side (`planGaps`, tested in `test/alignment.test.ts`); lines inside a block widget other than its first are skipped. It re-runs 50 ms after any height change in either editor (edits, wrapping, rendered blocks, lines measured as they scroll into view) and only dispatches when a gap changes by a pixel or more, so it settles. With the gaps, `startScrollSync` scrolls both editors to the same offset from the top of the note; without them it maps the top line through the matched headings.

With live updates on, edits in either note of the pair re-run the comparison 300 ms after the last keystroke; with live updates off, only undo and redo do (a CodeMirror update listener in `main.ts`), so undoing a copied difference brings its highlights back.

Each difference (`DiffHunk`) is a block of consecutive differing lines with its first line on both sides (`leftStart`, `rightStart`), also on a side without lines, where it marks the place the lines would go. `src/diff/copy.ts` turns a block into the edit that makes the other side's lines equal (`copyBlockEdit`, tested in `test/copy.test.ts` by copying every difference until both texts are equal). `src/compare/copyDifference.ts` runs it: it refreshes the comparison so the blocks match the text as it is now, edits the target note through its `Editor` (so the edit lands in that note's undo history), and moves the cursor there so Cmd+Z undoes it. Cmd+click is a CodeMirror `mousedown` handler on the pair's editors that skips links and tags; the right-click items come from the `editor-menu` event, and the two commands act on the cursor's difference.

The plugin uses no Node or Electron APIs and makes no network requests, so `isDesktopOnly` is `false`.

## Release

1. `npm version <x.y.z>` sets the version in `package.json`, `manifest.json` and `versions.json` (through `version-bump.mjs`), commits, and tags the commit `x.y.z` without a `v`.
2. `git push --follow-tags` starts `.github/workflows/release.yml`, which checks that the tag matches `manifest.json`, builds, tests, lints and opens a draft release with `main.js`, `manifest.json` and `styles.css` attached.
3. Review the draft on GitHub and publish it. Obsidian offers the update to users once the release is published.

Raise `minAppVersion` in `manifest.json` before `npm version` when a release needs a newer Obsidian.
